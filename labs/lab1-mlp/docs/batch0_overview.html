Batch 0 · Laboratorio #1 — MLP

Andamiaje del repositorio

Antes de tocar una sola línea de PyTorch, se organiza el repositorio del curso y se prepara el entorno de ejecución. Este documento explica qué se construyó, por qué, y qué conceptos hay detrás.

Qué se hizo

Se creó la estructura de carpetas del curso completo (no solo de este laboratorio), un entorno virtual de Python aislado con las dependencias exactas que pide el enunciado, y el esqueleto del notebook con los encabezados de cada sección del PDF.

deepLearning/
├── README.md                 # mapa del repo + setup
├── requirements.txt           # torch, jupyter, pandas, numpy, matplotlib, scikit-learn
├── .venv/                     # entorno aislado (no se versiona)
├── labs/
│   └── lab1-mlp/
│       ├── lab1_mlp.ipynb    # el entregable
│       ├── data/              # housing.csv (no se versiona)
│       └── docs/              # estos explicadores HTML
├── hdt/                       # hojas de trabajo futuras
└── projects/                  # proyectos futuros

Por qué así

Pros

  • Entorno virtual evita que torch choque con otras versiones instaladas en el sistema.
  • Separar labs/, hdt/ y projects/ deja espacio para el resto del curso sin reorganizar después.
  • El notebook se genera y ejecuta programáticamente (nbformat + nbconvert), así que cada entrega en el repo ya tiene las salidas (gráficas, tablas) horneadas — no depende de que alguien le dé "Run All" manualmente.

Contras / límites

  • Un entorno virtual por proyecto es más pesado en disco que uno global (~1–2 GB con torch CPU).
  • data/ queda fuera de git: quien clone el repo debe volver a descargar housing.csv.
  • La estructura para hdt/ y projects/ es especulativa — se ajustará cuando exista contenido real.

Impedimentos encontrados

El sistema no tenía torch ni jupyter instalados (sí tenía pandas/numpy/matplotlib/scikit-learn). Se resolvió creando .venv e instalando requirements.txt dentro de él — sin tocar el Python del sistema.

Verificado: python -c "import torch; print(torch.__version__)" dentro del venv reporta torch 2.13.0 y el notebook esqueleto se ejecutó de punta a punta sin errores vía jupyter nbconvert --execute.

Glosario básico

MLP (Multilayer Perceptron)
Red neuronal formada por capas totalmente conectadas ("densas") apiladas, cada una seguida de una función de activación no lineal. Es la arquitectura base para regresión y clasificación tabular.
Entorno virtual (venv)
Copia aislada del intérprete de Python con su propio conjunto de paquetes, para que las dependencias de un proyecto no interfieran con las de otro.
Jupyter Notebook (.ipynb)
Documento ejecutable que mezcla celdas de código (Python) y celdas de texto (Markdown), con las salidas (tablas, gráficas) guardadas junto al código.
nbconvert --execute
Herramienta de línea de comandos que ejecuta un notebook de principio a fin y guarda las salidas resultantes, usada aquí para asegurar que cada batch entregado ya corrió sin errores.

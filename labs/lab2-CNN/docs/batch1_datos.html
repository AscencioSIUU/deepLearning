Batch 1 · Laboratorio #2 — CNN

Datos y preparación

MNIST: 70,000 dígitos manuscritos, 28×28 en escala de grises. La exploración es rápida porque el dataset ya viene limpio — el trabajo real es dejar el test set intocable.

Qué se hizo

Se descargó MNIST vía torchvision.datasets.MNIST (60,000 train / 10,000 test), se respondieron las 4 preguntas de exploración del enunciado, se visualizaron 10 ejemplos etiquetados y se dividió el train set en train/val (90/10) dejando el test set sin tocar hasta la evaluación final.

Decisiones y por qué

Pros del enfoque

  • Normalización con la media/desviación estándar conocidas de MNIST (0.1307 / 0.3081) en vez de recalcularlas — valores estándar, reproducibles y ya validados por la comunidad para este dataset exacto.
  • Split 90/10 sobre train deja 6,000 imágenes de validación — suficiente volumen para que accuracy/F1 de validación no sean ruidosas entre iteraciones.
  • test_ds se construye pero no se usa hasta la sección 5: cero posibilidad de fuga de información durante la búsqueda de hiperparámetros.

Contras / límites

  • No se aplicó data augmentation (rotaciones, traslaciones) en esta etapa — MNIST es lo bastante fácil que el enunciado no lo exige; candidato a mejora futura.
  • El split 90/10 es fijo (no k-fold): con presupuesto de tiempo por iteración, una validación holdout simple es suficiente y más rápida de iterar.

Investigación detallada: por qué normalizar antes de la CNN/MLP

Igual que en el Lab #1, el descenso de gradiente converge mejor con entradas centradas cerca de 0 y de escala comparable. MNIST ya tiene todos los píxeles en la misma unidad (intensidad de gris), así que la normalización aquí no resuelve un problema de escalas dispares entre features (como en housing) sino que centra la distribución: de [0, 1] tras ToTensor() a media ≈0, varianza ≈1 tras Normalize, lo que evita que la activación inicial de las primeras capas esté sesgada hacia valores positivos (la mayoría de píxeles en MNIST son fondo negro = 0).

Impedimentos encontrados

El entorno virtual del repo (../.venv) tenía torch pero no torchvision. Se instaló con pip install torchvision — quedó fijado en requirements.txt del repo para reproducibilidad.

Qué más se podría hacer

  • Data augmentation (rotación ligera, traslación) para la CNN en iteraciones posteriores, si se busca exprimir el último punto de accuracy.
  • K-fold cross-validation en vez de un split holdout único, si el presupuesto de tiempo lo permitiera — no es necesario aquí por el tamaño de val (6k).

Glosario

Tensor
Arreglo multidimensional (generalización de escalar/vector/matriz) que PyTorch usa para representar datos y parámetros, con soporte para autograd y ejecución en GPU/MPS.
ToTensor()
Transform de torchvision que convierte una imagen PIL (uint8, [0,255]) a un tensor float32 en [0,1], reordenando a formato canal-primero (C×H×W).
Normalize(mean, std)
Transform que resta la media y divide entre la desviación estándar por canal, dejando la entrada centrada en 0 con varianza ≈1.
Fuga de datos (data leakage)
Cuando información del test set influye, directa o indirectamente, en decisiones de entrenamiento o hiperparámetros. Por eso test_ds se aísla desde este batch.
